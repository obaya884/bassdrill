## 1. 背景

オーナーはベースのレッスンに通っており、先生から次の基本練習メニューを毎日の自主練として課されている。

1. キーを決める
2. メジャースケール
3. ペンタトニックスケール（メジャーペンタと、平行調のマイナーペンタ）
4. セブンスコード 4 種（M7・m7・7・m7♭5。キーの音を根音にする）
5. 度数（メジャースケールの音からランダムに出題し、答える）
6. ダイアトニックコード
7. ノンダイアトニックコード

ところが自主練では、このメニューが素直に回らない。原因はメニューの難しさではなく、**ベースを構えてから手が止まる箇所**が決まっていることにある。

- 「今日はどのキーでやるか」を決めるところで毎回立ち止まる
- 指板上の位置と音名が頭の中でまだ結びついておらず、スケールを弾きながら「この音は何だっけ」で止まる。答え合わせする手段が手元にない
- 度数の練習は、レッスンでは先生が「C から見て 4 度は？」「G から見た B は？」と出題してくれるが、一人だと自問できず成立しない
- ダイアトニック・ノンダイアトニックのように理屈が要る項目は、何をどの順に弾くのかを思い出すところで止まる

いずれも、**見れば分かるものが目の前に出ていれば止まらない**種類のつまずきである。紙に書いた指板図やコード表でも代用できるが、キーごとに書き直すことになり、紙は見る気を起こさせない。

## 2. 目的

ベースを構えて画面を見れば、キーが決まっていて、押さえる場所と音名が見えて、次に何をするかが分かる状態を作る。それによって基本練習メニューを**毎回・止まらずに・一周**できるようにする。

### 2.1 成功基準

次の 3 つが満たされたとき、本プロジェクトは成功したと言う。

1. **オーナーが自主練のたびに本アプリを開き、メニューを一周している**（紙や記憶に戻らない）
2. **キーを決める・押さえる場所を探す・次の項目を思い出す、のどれでも手が止まらない**
3. **レッスンで先生の度数の出題に、以前より速く答えられている**

## 3. 対象ユーザーと利用シーン

- **対象ユーザー**: オーナー本人（シングルユーザー）。他者への公開は現時点でスコープ外（§7）
- **利用シーン**:
  - **自宅での自主練（主）**: ベースを構え、横の PC モニターに本アプリを映して、上から順にメニューを進める。次の節へはマウスのスクロールで流す。1 回の練習で 1 キー、余裕があれば 2〜3 キー
  - **移動中・楽器なし**: スマホで開き、度数の出題に頭の中で答える、スケールやコードの構成音を目で確認する。片手で持って親指だけで進める
  - **レッスン中**: スマホで開き、今のキーのスケール・コード・外れ音を先生に見せる、言われたキーに切り替えて確認する
- **利用環境**: PC のブラウザ（大画面）が主。両手はベースにあるので、操作はマウスのスクロールと少ないクリックで済むこと（C-3）。スマホ（縦持ち・横持ち）でも同じ内容を、タッチとスワイプで進められること（§6.6）。タブレットはスマホ表示で動けばよい。**キーボードは使わない**（§7）
- **前提知識**: 利用者はメジャースケール・度数・セブンスコード・ダイアトニックの概念は教わっている。本アプリは理論を教えるものではなく、**思い出させる**もの

## 4. コンセプトと用語: 止まらない基礎練

本アプリは先生の代わりに「今日のキー」を決め、指板を見せ、度数を出題し、コードの一覧を並べる。利用者は決めない・探さない・思い出さない。練習に使う判断をすべて画面側が先に済ませておく。

```
開く ──▶ 今日のキーが決まっている ──▶ メジャースケール ──▶ ペンタ ──▶ セブンス 4 種
                                                                            │
   「次のキー」でもう一周 ◀── ノンダイアトニック ◀── ダイアトニック ◀── 度数（出題）◀┘
```

### 4.1 用語

| 用語 | 意味 |
|---|---|
| キー | その回の練習で基準にするメジャーキー。全 12 キー |
| 今日のキー | 開いた日付から一意に決まるキー（F-101）。同じ日は何度開いても同じ |
| 指板 | 4 弦ベース（E-A-D-G）の指板図。開放弦を含む。音名と度数を載せる（F-201） |
| 度数 | 基準の音から数えた位置。基準がキーの根音なら**キー度数**（スケール上の位置 1〜7。長短は付けない）、コードの根音なら**コード度数**（1・3・5・7 に ♭ を付けて質を表す。例 m7 は 1 ♭3 5 ♭7）。度数の出題（F-401）はキー度数、コードの表示（F-301〜F-303）はコード度数で、画面上もラベルを分ける |
| セブンスコード 4 種 | キーの音を根音にした M7・m7・7・m7♭5 |
| ダイアトニックコード | キーのメジャースケール上に作る 7 つのセブンスコード（IM7・IIm7・IIIm7・IVM7・V7・VIm7・VIIm7♭5） |
| ノンダイアトニックコード | ダイアトニックでないコードのうち、J-POP・Rock でよく使われる 8 つ（I7・II7・III7・IVmM7・Vm7・VI7・♭VIM7・♭VII7）。レッスンのホワイトボードが出所（[決定ログ](./log_11_要求定義書.md) 2026-11-05） |
| 外れ音 | コードの構成音のうち、キーのメジャースケールに含まれない音。ノンダイアトニックコードでベースラインに取り入れると効く音 |
| 節 | 画面上の 1 項目（キー・スケール・ペンタ・セブンス・度数・ダイアトニック・ノンダイアトニック）。メニューの 1 行に対応する |

## 5. 重視する価値

機能の要否や優先度で迷ったとき、次の順で判断する。番号は要件定義書ほか各文書からの参照用。

| ID | 価値 | 意味 |
|---|---|---|
| C-1 | **立ち止まらない** | 利用者が決める・探す・思い出す場面を作らない。キーは画面が決め、次にやることは画面に出ている。選択肢を増やすより既定を強くする |
| C-2 | **見れば分かる** | 指板の上に音名と度数の両方が載っていて、答え合わせが一目でできる。文章での説明より図を優先する |
| C-3 | **操作を覚えない** | PC でもスマホでも、見えているものをスクロール・クリック・タップ・スワイプするだけで進む。隠れた操作（キーボードショートカット、長押し、ジェスチャの組み合わせ）を覚えさせない。両手はベースにあるので、操作の回数そのものを少なくする |
| C-4 | **開きたくなる** | 画面を目に入れると練習したくなる見た目であること。情報を絞って大きく見せる。紙に戻りたくならない |
| C-5 | **先生の言うことに合わせる** | 練習の内容（メニュー・コードの並び・出題形式）はレッスンで言われた形に合わせ、アプリ側で理論的に正しくても勝手に広げない |

価値が衝突したら小さい番号を優先する。ただし C-5 は内容の正しさに関する前提であり、C-1〜C-4 のために練習内容を変えることはしない。

## 6. 要求

製品が何をできるか（機能要求 F-XXX。§6.1〜§6.5）と、どの機能にも掛かる品質と制約（非機能要求 N-XX。§6.6）の全体。**この表が製品の地図**で、実装済みのものも将来のものも同じ表に載せる。要求の実現方針は[要件定義書](./12_要件定義書.md) §5 が持つ。

- **番号**: 百の位が領域を表す（1xx キー／2xx 指板とスケール／3xx コード／4xx 度数／5xx 画面全体と操作／6xx スマホ表示）。領域の中は起こした順で、並び替えない
- **優先度**: **Must**（ないとメニューが一周できない）／ **Should**（一周はできるが、止まる場面が残る）／ **Could**（将来の候補）。やらないと決めたものは表から外して §7 スコープ外へ落とす

## 7. スコープ外

やらないと決めたもの。将来の候補は「候補」と明記する。

| 項目 | 扱い | 理由 |
|---|---|---|
| 音を鳴らす・録音する・弾いた音を判定する | 対象外 | 本アプリは見せるもの。採点は先生がする。C-5 |
| メトロノーム・バッキングトラック | 対象外 | 既存のアプリで足りる。本アプリに足すと情報が増える。C-4 |
| 練習ログ（何日やったか・何キーやったか） | 対象外 | 日々の実行記録は hitosuji が持つ（LifeOS の責務分離）。本アプリに記録を持たせない |
| 理論の解説ページ | 対象外 | 思い出させるのが役目で、教えるのは先生。一行のガイド（F-303）で止める |
| タブレット専用のレイアウト | 対象外 | スマホ表示（§6.6）か PC 表示のどちらかで動けばよい（N-03） |
| キーボードショートカット | 対象外（2026-11-05 に廃止） | PC とスマホで操作を揃え、隠れた操作を覚えさせない（C-3）。初版では J/K・Space・N 等で操作したが、見えるボタンとスクロールに置き換えた |
| 度数の自動送り（一定秒で答えと次が出る） | 対象外（2026-11-05 に廃止） | 使ってみて要らなかった。間隔の設定と保存ごと外し、カードの「答え」「次」ボタンだけにする |
| スマホのホーム画面への追加（PWA）・オフライン動作 | **候補** | 移動中の利用（§3）で要るようになったら起こす。静的サイトなので足すのは容易 |
| 5 弦・6 弦ベース、変則チューニング | 対象外 | オーナーの楽器は 4 弦標準チューニング。候補にもしない |
| マイナーキー（ナチュラル・ハーモニック等）のスケール | 対象外 | メニューにない。C-5。平行調のマイナーペンタは F-202 に含む |
| 他者への公開・アカウント・共有 | 対象外 | シングルユーザー（§3）。N-02 |
| 任意のコード進行の入力・表示 | **候補** | 「好きな曲のコードを弾く」練習は別のメニュー。要るようになったら要求に起こす |
| 度数の出題での長短（長 3 度・短 3 度）の区別 | **候補** | 先生の出題は数字だけ。区別が要ると分かったら F-401 を直す |

## 8. プラットフォームと技術方針

- **PC のブラウザで動く Web アプリ**。インストール不要で、どの PC からも同じ URL で開ける
- **サーバー・DB は持たない**（N-02）。静的なページとして配信し、状態はブラウザ内に置く
- 技術は「早く動く」を優先し、Vite + React + TypeScript + Tailwind CSS の SPA にする（React・Tailwind・Vitest は hitosuji と共通で、フレームワークの約束事だけを減らす）。ホスティングは Vercel 無料枠（N-06）。具体は[要件定義書](./12_要件定義書.md) §2
- 原案にあったデスクトップアプリ（Jetpack Compose・SwiftUI）は採らない（[決定ログ](./log_11_要求定義書.md) 2026-11-05）

## 9. 名称

- 名称は **Bass Drill**（ベースの基礎練習＝ドリル）。リポジトリ名・ディレクトリ名・識別子は小文字でハイフンなしの `bassdrill`（hitosuji と同じ流儀）
- 公開しないので正式名称との区別は設けない

## 10. 前提と制約

- 個人開発。趣味ペースで、日付ではなく順序で進める
- 開発は AI 主導（Claude Code）で行う。仕様が正でコードは従う。文書の構成・規約は hitosuji・Re-Buy に倣う
- 練習メニューの内容はレッスンに従う（C-5）。先生の指示が変わったら要求を直す
- 原案と手書きの画面イメージは LifeOS Vault の Fleeting にあり、本書に取り込んだ時点で役目を終える
