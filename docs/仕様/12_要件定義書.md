## 1. 本書の位置づけ

要求定義書の要求（F-XXX・N-XX）を、実装可能な要件に落とし込む。**要求 1 つにつき 1 行で「その機能が何をするか」の規則——起きること・条件・例外——を持つ**のが本書 §5。画面の構成・寸法・色・文言は[画面定義書](./13_画面定義書.md)が持つ。本書 §5 に残る見え方の記述は挙動を説明するための最小限で、数値と色は 13 が正。

## 2. システム方式

### 2.1 全体構成

```
[ブラウザ (Chrome, PC)]
        │ HTTPS（静的ファイルの取得のみ。以後の通信なし）
        ▼
[静的サイト: Vite + React (TypeScript) の SPA をビルドした dist/]  ← Vercel 無料枠
        │
   すべての計算（キー決定・音名・コード・出題）はブラウザ内で完結
   その場の設定だけ localStorage に置く
```

### 2.2 技術スタック選定

| レイヤ | 採用 | 選定理由（対応する要求） |
|---|---|---|
| ビルド | Vite + React + TypeScript（SPA。ルーティングなし） | ページが 1 枚でサーバー機能を使わない（N-02）ので、フレームワークの約束事が最も少ない構成を採る（要求定義書 §8、[決定ログ](./log_11_要求定義書.md) 2026-11-05）。React・Tailwind・Vitest は hitosuji と共通 |
| UI | React + Tailwind CSS | 装飾を自前で組む。指板は SVG で描く（文字を載せる・拡大しても崩れない） |
| 状態 | React の state + localStorage | 持つデータが「その場の設定」だけ（F-505・N-02）。DB・ORM は持たない |
| テスト | Vitest（domain の純粋関数） | N-04。12 キー全件の導出を表で検証する |
| ホスティング | Vercel 無料枠 | N-06。main への push で自動デプロイ |
| 認証 | なし | 練習内容しか表示せず、個人データを持たない（N-02）。URL を知られても困らない |

### 2.3 コード構成

```
src/domain/      音楽理論の純粋関数（音名・調号・スケール・コード・外れ音・出題・キー順列）。I/O と Date を持たず引数で受ける
src/app/         画面の組み立て（`App.tsx` が表示モードで PC とスマホの木を分け、状態は `useDrillState` が持つ）
src/components/  指板・5 度圏・コード表・出題などの部品
```

依存方向は domain ← components ← app（エントリは `src/main.tsx`）。**domain は React を知らない。** 理論の正しさはすべて domain のテストで守る（N-04）。アーキテクチャ定義書（15）は作らず、この節で足りなくなったら起こす。

### 2.4 リポジトリ・環境

- 単一リポジトリ `bassdrill`。main への push で Vercel に自動デプロイ
- 環境は production のみ。ローカルは `vite`（`npm run dev`）。ビルドは `vite build` で `dist/` に出し、Vercel はそれを配信する（framework preset は Vite）
- GitHub の obaya884/bassdrill に public で置く（2026-11-05 オーナー決定）

## 5. 要件

要求 ID 単位の挙動の規則。見え方の詳細は画面定義書（13）ができたらそちらへ移す。本書で「スケール」と書いたら今のキーのメジャースケール、「音名」は F-105 の綴りに従う。節の名前は `スケール / ペンタ / セブンス / 度数 / ダイアトニック / ノンダイアトニック` の 6 つで、番号は付けない。

### 5.1 キー

| 要求ID | 要件 |
|---|---|
| F-101 | 開いたまま日付をまたいだときは、1 分ごとの確認とタブの復帰で今日のキーに切り替え、順列の位置・手で選んだキー・コードの選択を初期に戻す。見ている場所（PC のスクロール位置・スマホの節）は動かさない。Asia/Tokyo の暦日を 1970-01-01 からの通算日 `d` にし、`d` を 12 で割った商 `b` を種にした決定的な疑似乱数で 12 キーの順列 `P(b)` を作る。**今日のキー**は `P(b)[d mod 12]`。これで 12 日ごとのブロックで全キーが 1 回ずつ出る。ブロックの境目で `P(b+1)[0]` が `P(b)[11]` と同じになったら `P(b+1)` の先頭 2 つを入れ替える（同じキーが 2 日続かない）。同じ日は何度開いても同じキーで、保存は要らない（[決定ログ](./log_12_要件定義書.md)） |
| F-102 | 「次のキー」（キー選択の面の中のボタン。F-104）で今日のキーから順列 `P(b)` を 1 つ進める（末尾の次は先頭。つまり 2 つ目のキーは明日のキーと同じ）。今日何番目まで進んだかを F-505 で保存し、開き直しても続きから進む。キーが変わると全節の内容が新しいキーで描き直され、コードの選択は先頭に戻り、度数の出題は作り直す。見ている場所（PC のスクロール位置・スマホの節）は動かさない |
| F-103 | ヘッダー（上部固定）に今のキーを大きく出す。PC 表示ではその横に 5 度圏を描く: 時計回りに `C G D A E B G♭ D♭ A♭ E♭ B♭ F` の 12 を円に並べ、今のキーを強調する（色と大きさの両方）。スマホ表示では 5 度圏を出さない（F-604） |
| F-104 | ヘッダーのキーはボタン。クリック／タップで**キー選択の面**（PC はキーの下に出るポップオーバー、スマホは下から出るシート）が開き、12 キーを 5 度圏の順に 4 列 × 3 段で並べ、今のキーを強調する。面の中に「次のキー」ボタン（F-102）も置く。キーを選ぶか「次のキー」を押すと面は閉じる。面の外をクリック／タップしても閉じる。手で選んだキーはその日の間だけ覚え（F-505）、「次のキー」で解除して順列の次へ進む。PC では 5 度圏の各キーのクリックでも同じに選べる |
| F-105 | 12 キーの綴りは `C G D A E B G♭ D♭ A♭ E♭ B♭ F`（6 つの ♯/♭ のキーは G♭ とする。[決定ログ](./log_12_要件定義書.md)）。スケールの 7 音は**文字を 1 つずつ進めて**綴る（C D E F G A B の順に各文字を 1 回ずつ使い、♯/♭ で合わせる）。これにより同じキーの中で同じ文字が 2 回出ることも、♯ と ♭ が混ざることもない |

### 5.2 指板とスケール

| 要求ID | 要件 |
|---|---|
| F-201 | 指板は横長で、弦は上から G・D・A・E（譜面・タブ譜の慣習）、左端が開放弦（0 フレット）、右へフレットが進む。3・5・7・9・12 フレットにポジションマークを置く。スケールの 7 音の位置すべてに丸を置き、丸の中に**音名**、丸の脇か下に**度数**を出す。根音（1 度）は丸の色を変え、かつ太い縁を持つ（色だけに頼らない）。スケール外の位置には何も置かない |
| F-202 | ペンタの節は F-201 と同じ指板に、メジャーペンタ（スケールの 1・2・3・5・6）を出す。節の中の `メジャー / マイナー` ボタンでメジャーペンタとマイナーペンタ（平行調。音は同じで、根音を 6 度の音とし、度数を**マイナーペンタの根音から数え直して** 1・♭3・4・5・♭7 と出す）を切り替える。見出しに「C メジャーペンタ」「A マイナーペンタ」のように今の名前を出す |
| F-203 | PC 表示では 0〜12 フレットの 13 列を横スクロールなしで一画面に収める。想定する横幅は 1280px 以上（N-03）。スマホ表示では F-603 |
| F-204 | （Could・未詰め）設定でフレット数を変える案。着手時に決める |
| F-205 | （Could・未詰め）指板の空いている位置にマウスを置くと音名と度数（スケール外なら「スケール外」と半音の度数）を出す案。C-3 の例外（マウスを使う）なので、要るかどうかを使って見極める |

### 5.3 コード

| 要求ID | 要件 |
|---|---|
| F-301 | セブンスの節は根音をキーの音に固定した 4 コードを `M7 → m7 → 7 → m7♭5` の順で並べる（レッスンの順）。各コードの行にコードネーム（例 `CM7`）と、構成音 4 つを「度数（`1 3 5 7` / `1 ♭3 5 ♭7` / `1 3 5 ♭7` / `1 ♭3 ♭5 ♭7`）＋音名」の対で出す。選択中のコードの構成音を指板に出す（丸の中は音名、脇は**コード度数**。根音は F-201 と同じ強調）。表と指板のラベルは「コード度数」とし、スケール・度数の節の「キー度数」と区別する（要求定義書 §4.1） |
| F-302 | ダイアトニックの節はスケールの各音を根音にしたセブンスコード 7 つを `IM7 IIm7 IIIm7 IVM7 V7 VIm7 VIIm7♭5` の順で並べる。各行にローマ数字・コードネーム（例 `Dm7`）・構成音（コード内の度数 `1 ♭3 5 ♭7` ＋音名）を出す。選択中のコードを指板に出す（F-301 と同じ） |
| F-303 | ノンダイアトニックの節は 8 つを `I7 II7 III7 IVmM7 Vm7 VI7 ♭VIM7 ♭VII7` の順で並べる（レッスンのホワイトボードの順。キー C なら `C7 D7 E7 FmM7 Gm7 A7 A♭M7 B♭7`）。構成音のうち**スケールに無い音（外れ音）**を、表でも指板でも強調する（色と下線）。根音がスケール外のコード（♭VIM7・♭VII7）は根音も外れ音として強調する。節の見出しの下に「ダイアトニックでないコードは無数にあるが、J-POP・Rock でよく使われるのはこの 8 つ。スケールから外れた音をベースラインに取り入れるとよい」の一行を固定で出す |
| F-304 | 節 セブンス・ダイアトニック・ノンダイアトニックのコード表は、行のクリック／タップでそのコードを選択し、指板がそのコードの構成音に変わる。節に入ったときの選択は前回の位置を保ち、キーが変わったとき（F-102・F-104）と日付が変わったときに先頭へ戻る |
| F-305 | コードの構成音は**根音の文字から 3 度ずつ文字を進めて**綴る（3 度＝文字を 2 つ進める、5 度＝4 つ、7 度＝6 つ）。半音数が合うように ♯/♭ を付ける。例: キー C の D7 → D・F♯・A・C（♭3 なら F）。A♭M7 → A♭・C・E♭・G。B♭7 → B♭・D・F・A♭。♭VI・♭VII の根音はスケールの 6 度・7 度の文字を ♭ で下げたもの。**この綴りにダブルシャープ・ダブルフラットが 1 つでも含まれるコードは、根音を同じ高さの別の綴り（G♭ → F♯、D♭ → C♯、A♭ → G♯、E♭ → D♯、D♯ → E♭、B𝄫 → A、E𝄫 → D、C♭ → B、F♭ → E）に読み替えてから同じ規則で綴り直す**。該当は 12 キー総当たりで 12 箇所（♭ 系 4 キーの m7♭5 と G♭m7、キー B の III7、キー D♭・G♭ の IVmM7・♭VIM7・♭VII7）で、読み替え後はすべて変化記号 1 つ以内に収まる（キー D♭ の IVmM7 = F♯mM7 の 7 度 E♯ のように、理論どおりの綴りが残るものは残す）。コードネームとローマ数字は読み替え後の根音で出す（キー D♭ の ♭VIM7 は `AM7`。ローマ数字は `♭VIM7` のまま）。この 12 箇所はテストの期待値に明示する |

### 5.4 度数

| 要求ID | 要件 |
|---|---|
| F-401 | 度数の節は 1 問ずつ出す。**形式 A（度数→音名）**: 「`G` から見て `4` 度は？」、答え `C`。**形式 B（音名→度数）**: 「`G` から見た `B` は？」、答え `3 度`。基準の音はスケール 7 音から、問われる音（形式 A では度数、形式 B では音名）は基準以外の 6 つから選ぶ。度数は**スケール上の位置の差**（基準からスケールを上に数えて何番目か）で 2〜7。長短は付けない。基準と答えが同じ（1 度）は出さない（要求定義書 §11） |
| F-402 | 形式 A・B を 1:1 で混ぜ、直前の問題と「形式・基準・問われる音」がすべて同じにはしない。乱数は Math.random でよい（F-101 の決定的乱数とは別） |
| F-403 | 問題の状態は `出題中 → 答え表示 → 次の出題中` の繰り返し。問題カードの中に 1 つのボタンがあり、出題中は `答え`、答え表示中は `次` と表示が変わる。押すと次の状態へ進む。答え表示では、答え（音名または度数）を問題文と同じ大きさで出し、指板に**基準の音と答えの音の 2 つ**を出す（基準は根音の強調、答えは通常の丸。他の位置は出さない）。カードのボタン以外の場所をクリック／タップしても何も起きない |
| F-404 | （欠番。自動送りは廃止） |
| F-405 | （Could・未詰め）設定で形式を A のみ／B のみに絞る案 |

### 5.5 画面全体と操作

| 要求ID | 要件 |
|---|---|
| F-501 | **PC 表示**（§5.7 の判定で幅の広いとき）。S-01 は 6 節を縦に並べた 1 ページ。節の順は `スケール / ペンタトニック / セブンスコード / 度数 / ダイアトニック / ノンダイアトニック` で、番号は付けない。すべての節を等倍で描き、減光や拡大はしない。利用者はマウスのスクロールで上から読み進める。「今どの節か」の状態は PC では持たない。ヘッダー（キー・5 度圏）は上部固定で、スクロールしても常に見える |

| F-503 | （欠番。現在地の表示は PC では持たず、スマホは F-601 の点） |
| F-504 | 暗い背景に、指板の丸と今のキーを 1 色のアクセントで浮かせ、根音と外れ音にそれぞれ別の 1 色を使う。装飾は指板と 5 度圏だけで、枠線・影・アイコンは足さない。色・寸法・フォントは[画面定義書](./13_画面定義書.md) §5 が正 |
| F-505 | localStorage に `{ 日付, 今日の順列の位置（0〜11）, 手で選んだキー（無ければ null） }` を置く。日付が今日と一致するときだけ位置と手で選んだキーを使い、違えば位置 0・手の選択なしに戻す。localStorage が使えない環境では既定値で動き、エラーにしない。過去に保存された `intervalSec` は無視する |

### 5.6 非機能

要求定義書 §6.7 の N-XX ごとに、どこで何によって成り立たせているか。

| 要求ID | 要件 |
|---|---|
| N-01 | ビルド成果物は静的ファイルだけで、初回表示に要る JS を 1 バンドルに留める（外部フォントは 1 書体まで）。開いた直後の表示はサーバーの計算を待たず、ブラウザ内で今日のキーを決めて描く。節の移動・答えの表示は state の更新だけで、通信しない |
| N-02 | バックエンド・DB・認証を持たない（§2）。ブラウザに置くのは F-505 の項目だけで、消えても次に開けば既定値で動く |
| N-03 | PC 表示の動作確認は Chrome 最新・横幅 1280px 以上、スマホ表示は iOS Safari と Android Chrome の最新で縦持ち・横持ちの両方を確認する。表示の切り替え幅は §5.7。1024〜1279px の PC 表示と、タブレット・他ブラウザは、崩れても要求違反にしない |
| N-04 | `src/domain` の純粋関数に対して、**12 キー × { スケール 7 音・メジャー／マイナーペンタ・セブンス 4 種・ダイアトニック 7・ノンダイアトニック 8 とその外れ音 }** を期待値の表で検証する。綴り（F-105・F-305）も期待値に含める。出題（F-401・F-402）は「基準≠答え」「直前と同一でない」「度数の計算」を検証する。テストが無い導出を画面に出さない |
| N-05 | 1 m 離れて読める文字の大きさは[画面定義書](./13_画面定義書.md) §5 の文字サイズ表が正（指板の音名 18px・出題と答え 56px・節の見出し 28px）。実機で読めなければ 13 を直す |
| N-06 | Vercel 無料枠。外部の有料 API・フォントサービスを使わない（Google Fonts は可） |
| N-07 | 画面の文言は日本語で、音名・コードネーム・度数記号は英語表記（`C` `Dm7` `♭VII7`）。♯・♭は記号（`♯` `♭`）で出し、`#` `b` は使わない |

| F-601 | **表示の判定**: ビューポートの幅が 1024px 未満、**または**主な入力手段がタッチ（`(pointer: coarse)` が真）ならスマホ表示、それ以外は PC 表示（iPad 横持ちなど幅の広いタッチ端末はスマホ表示）。幅が変わったら（回転・ウィンドウ変更）その場で切り替え、コードの選択・出題の状態・キーは引き継ぐ。スマホ表示は 6 節を横に並べたページで、1 画面に 1 節だけが見える。**横スワイプ**（指板の外。F-603）で前後の節へ移り、端では止まる（巡回しない）。ヘッダーの下に 6 つの点を並べ、いまの節を強調する。点の両脇の `‹` `›` ボタンでも移れる。スマホで見る節は状態として持ち、PC 表示の間も保つ（PC→スマホで切り替わったとき、スマホで最後に見ていた節に戻る。初回は先頭のスケール） |
| F-602 | 画面下部のバーは持たない。節の中の操作はすべて節の中にある: コード表の行タップ（F-304）、度数カードの `答え` / `次` ボタン（F-403）、ペンタの `メジャー / マイナー` ボタン（F-202）。「次のキー」はキー選択のシート（F-104）の中。ボタンはすべて 44px 以上の高さ |
| F-603 | 指板は PC と同じ 13 列の SVG を、スマホ表示では幅の広い箱（寸法は 13 §8.3）に入れて横スクロールさせる（縦持ちで 5〜6 列、横持ちは機種の幅しだいで全列）。節を移ると左端（開放弦）に戻る。指板の領域で始まったタッチは指板のスクロール（横）か本体のスクロール（縦）に使い、節の移動（F-601）のスワイプ判定から除外する |
| F-604 | スマホ表示では 5 度圏（F-103）を出さず、ヘッダーのキーをタップして開くシート（F-104）だけでキーを選ぶ。**スマホ表示ではキーが変わっても節は動かさない**。シートが開いている間、帯のスワイプは効かない。シートはキーの選択・「次のキー」・外側のタップで閉じる（キーボードは使わない。F-502） |
