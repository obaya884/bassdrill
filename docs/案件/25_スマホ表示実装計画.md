# Bass Drill スマホ表示 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 要求定義書 §6.6（F-601〜F-606）を満たすスマホ表示を足し、PC 表示（§6.5）はそのままに、同じ URL が幅と入力手段で自動的に切り替わる状態で本番に出す。

**Architecture:** App の状態（キー・フォーカス・コード選択・出題・設定）を `useDrillState` に切り出し、`useDisplayMode` の判定で `DesktopApp`（現状の木）と `PhoneApp`（7 節を横に並べた帯＋下部バー＋シート）の**どちらか一方**を描く（F-606）。スワイプは Pointer Events を自前で受ける `useSwipe`。指板は既存の SVG を横スクロールの箱に入れるだけ。domain には触れない。

**Tech Stack:** 既存（Vite 8 / React 19 / TS 7 / Tailwind 4 / Vitest 5 + jsdom + Testing Library）。追加依存なし。目視は Playwright MCP の 390×844 と 844×390。

**Spec:** [要求定義書](../仕様/11_要求定義書.md) §6.6・N-03、[要件定義書](../仕様/12_要件定義書.md) §5.7（と F-102・F-104・F-304・F-403・F-404・F-502）、[画面定義書](../仕様/13_画面定義書.md) §8。

## Global Constraints

- スマホ表示の判定は「`innerWidth < 1024` または `(pointer: coarse)`」（F-601）。jsdom は `matchMedia` を持たないので `src/test/setup.ts` でポリフィルし、**既定は幅 1280・coarse なし**にする。スマホの木を描くテストは幅 390 を明示する
- 両方の木を描いて片方を隠さない（F-606）。状態は `useDrillState` が持ち、切り替えで失わない
- スマホ表示ではキーを変えても節に留まる。PC 表示では節 1 へ戻る（F-604・F-102）
- スワイプは Pointer Events。閾値 48px、縦移動より横移動が大きいとき。開始点が `[data-fretboard-scroll]` の中なら無視（13 §8.5・§8.3）。フォーカスの切り替えは `pointerup` で
- 帯は `touch-action: pan-y`、指板の箱は `pan-x pan-y`（13 §8.1・§8.3）
- ボタンの高さは 44px 以上（F-602）。文字サイズは 13 §8.7
- setState の更新関数の中で副作用を起こさない（CLAUDE.md）。StrictMode のテストを維持する
- コミットは日本語の Conventional Commits、末尾に `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`

## Review Focus

1. **回転・幅変更の途中で状態を失わない**: 出題中に PC↔スマホが切り替わっても問題・答え表示・コード選択・キーが同じ（Task 2 のテスト）
2. **指板の上から始めた横スワイプで節が動かない**: 開始点が指板の箱なら無視（Task 4）
3. **シートが開いている間のキー入力**: J/K/N は効かず、Escape だけ閉じる（Task 6）
4. **度数カードのタップは 1 段だけ進む**: StrictMode でも、48px 未満の移動でも 1 回の `advance`（Task 5）
5. **間隔シートの範囲と保存**: − ＋ が 2〜15 に収まり、F-505 で保存される（Task 6）
