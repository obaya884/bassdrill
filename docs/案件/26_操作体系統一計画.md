# Bass Drill 操作体系の統一 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2026-11-05 の仕様改訂（キーボード操作・自動送り・節「キー」・番号・`k / 12`・スマホの下部バー・PC のフォーカスの廃止、キー選択の面と「答え／次」ボタンの追加）を実装し、PC とスマホが同じ操作体系で動く状態で本番に出す。

**Architecture:** 状態（`useDrillState`）から自動送り・ヘルプ・キーボードの経路を外し、`focus` はスマホのページ位置としてだけ残す。PC は 6 節を等倍で縦に並べるだけの `DesktopApp`、スマホは下部バーを失くした `PhoneApp`。キー選択の中身（12 キー＋次のキー）と度数カード（答え／次ボタン）は PC・スマホで同じ部品を使い、包み（ポップオーバーかシートか）だけ変える。domain には触れない。

**Tech Stack:** 既存。追加依存なし。目視は Playwright MCP（1280×800 と 390×844）。

**Spec:** [要求定義書](../仕様/11_要求定義書.md) §5 C-3・§6.1・§6.4・§6.5・§6.6・§7、[要件定義書](../仕様/12_要件定義書.md) §5.1 F-102〜F-104・§5.2 F-202・§5.3 F-304・§5.4 F-403・§5.5・§5.7、[画面定義書](../仕様/13_画面定義書.md) 全節。

## Global Constraints

- `keydown` を購読しない（F-502）。`useKeyboard.ts`・`shortcuts.ts`・`ShortcutBar.tsx` は削除する
- 節は 6 つ `['scale','penta','seventh','quiz','diatonic','nonDiatonic']`。見出しに番号を付けない（F-501）
- キーを変えても見ている場所は動かない（F-102・F-104。PC はスクロール位置、スマホは節）
- localStorage は `{ date, keyOffset, manualKey }`。古い `intervalSec` は読まない（F-505）
- 度数カードのボタンは 1 つ。出題中 `答え`、答え表示中 `次`（F-403）。カードの他の場所は押しても何も起きない
- コード表の行はクリック／タップで選ぶ。PC でもスマホでも同じ（F-304）
- ボタンは 44px 以上（F-602）。文字サイズは 13 §5・§8.7
- setState の更新関数の中で副作用を起こさない（CLAUDE.md）。StrictMode のテストを維持する
- コミットは日本語の Conventional Commits、末尾に `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`

## Review Focus

1. **古い localStorage**: `intervalSec` や旧形式が残っていても既定値で起動する（Task 1）
2. **PC で「次のキー」後にスクロール位置が飛ばない**: 節の DOM を作り直さず、キーだけ変わる（Task 3 のテストで `section` 要素の同一性を確かめる）
3. **キー選択の面が開いている間のスマホのスワイプ**: 効かない（Task 4）
4. **度数カードのボタン以外のクリック／タップ**: 何も起きない。StrictMode でもボタン 1 回で 1 段（Task 2・Task 4）
5. **幅の切り替え**: PC→スマホ→PC で出題・答え表示・コード選択・キーを引き継ぐ（既存 App.test を残す）
